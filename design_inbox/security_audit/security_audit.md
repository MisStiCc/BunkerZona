## 2. П0 — грабли релиза с монетизацией (до включения биллинга)

1. **`StoreData.EMULATE_PURCHASES = true` в коде** — витрина с бесплатными
   покупками и кнопкой «∞ ВАЛЮТА» (`_grant_infinite_currency`: 10М
   биомассы/крутки/Искры/жетоны). Гейтинг = только константа; забудешь
   перевернуть — релиз с бесплатным всем. ФИКС: заменить оба флага на
   авто-детект `OS.is_debug_build()` (сборки редактора/дев-шаблона =
   эмуляция, релизный экспорт = биллинг) + оставить ручку-оверрайд:
   `const FORCE_EMULATE: bool = false` только для тестов. Тогда «забыть»
   невозможно физически.
2. **`StoreData.ENABLED = true` уже стоит** (для эмуляции) — то же самое:
   на релизе без биллинг-плагина витрина будет «мертвой или пустой».
   Один и тот же авто-детект решает оба пункта.
3. **Release-подпись = debug-ключ** (`export_presets`: `keystore/release`
   → `debug.keystore`, пароль «android» в тексте файла). Play такой APK
   примет, но: (а) пароль лежит в репо — если keystore однажды утечёт,
   им можно подписывать «обновления» под наш package; (б) смена ключа
   позже = новое приложение. ФИКС: сгенерировать отдельный
   `release.keystore` с длинным паролем, пароль НЕ коммитить
   (передавать сборщику; в export_presets оставить пустые поля и
   подставлять env-переменными/локально).

## 3. П1 — до публикации в Play

4. **PCK не шифрован** → GDScript извлекается и правится любым
   декомпилятором: клиентские проверки (цены, жетоны,Pass) = рекомендации.
   Включить шифрование экспорта (`encryption_include_filters="*.gd"`,
   ключ в env, НЕ в репо) — поднимает планку от «блокнота» до «нужен
   бинарь»; настоящую валидацию всё равно делает сервер (Этап 3).
5. **Сейвы — открытый `.res` в `user://`** (ResourceSaver без шифра):
   правится текстовым редактором ресурсов (крутки/жетоны/пропуск).
   Мера: `FileAccess.open_encrypted_with_pass` с ключом, выведенным из
   `OS.get_unique_id()` (+соль в коде) — от чужих рук и от «скачал сейв
   из интернета». Важно: ключ НЕ в git.
6. **Android `permissions/internet=false`** — при включении реального
   биллинга BillingManager потребует INTERNET: включить точечно тогда
   (не раньше — меньше пермиссий = меньше вопросов от Google).
7. **Android `allow_backup`** — проверить состояние (по умолчанию Godot
   true): бэкап Android переносит `user://` между устройствами — для
   сейвов-ресурсов это «перенос прогресса», приемлемо; при введении
   сервер-аккаунта — отключить (источник рассинхрона).

## 4. П2/П3 — гигиена и Этап 3

8. Git-мусор: `project_export.txt` (32 МБ дампа!), `tools/tmp_compile_check.gd`,
   `inbox/_done/anomaly_fx.log` — на удаление по решению владельца
   (уже в dead-code списке; добавить в один заход).
9. `android/build/` вывод на диске даёт 8 UID-дубликатов ворнингов
   редактору: периодически чистить папку (или `.gdignore` внутрь build).
10. **ЭТАП 3 (онлайн) — архитектурный закон безопасности:**
    - сервер — единственный авторитет по валютам/пропуску/жетонам; клиент
      присылает только отчёты (дневник событий уже спроектирован под это);
    - **никогда** не загружать с сервера/от игроков `.res`/`.tscn`
      (в Godot это исполнение кода) — только JSON/числа;
    - чат: HTML/BBCode-escaping, рейт-лимит, фильтр;
    - PlayFab (рекомендация консультации 30.10) или лёгкий свой бэкенд
      с валидацией чеков Play Developer API (анти-refund-фарм).
