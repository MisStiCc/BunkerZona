# Юридический аудит «Бункер: Зона» (27.10.2026)

Вердикт: **после правок этого аудита игра может публиковаться завтра**
(GitHub Releases + прямой APK). Публикация в Google Play требует
одного осознанного решения — §4 п.3. Монетизация — §5.

## 1. Товарный знак S.T.A.L.K.E.R. (GSC Game World)

### Что уже было чисто (сделано раньше, проверено)
- Имя игры везде: «Бункер: Зона» / Bunker: Zona (project.godot, локали
  menu.title/menu.title_top, бейдж «ФАНАТСКАЯ ИГРА», штамп версии).
- Юридический попап при первом запуске: «независимая фанатская игра по
  мотивам… не связана с GSC Game World… распространяется бесплатно» —
  образцовая форма дисклеймера фан-проекта.
- Внутриигровые тексты: слова «сталкер/Зона/Монолит/выброс» — нарицательные
  и жанровые термины, не охраняемые элементы. Имена мутантов — нарицательные
  существительные и фольклор (кровосос, полтергейст, зомби, химера…);
  внешность — CC0-модели Quaternius, лор-тексты и имена боссов — собственные.
  Ни один охраняемый образ GSC (логотип, шрифтовая стилизация S.T.A.L.K.E.R.,
  портреты персонажей, карты из игр) не воспроизводится.

### Найдено и исправлено в этом аудите
| Проблема | Риск | Правка |

| Шрифты OFL без текстов лицензии в репо | формальное нарушение OFL | канонические OFL.txt ×3 (google/fonts) + fonts/CREDITS.md |
| debug.keystore закоммичен в git (до появления .gitignore) | гигиена секретов | `git rm --cached`; файл на диске остался |
| package name = com.godot.game (дефолт) | Google Play отклоняет | → com.hakkiller.bunkerzona |

### Остаточные риски ТМ (осознанно принятые / ручки владельца)
- **Упоминание «по мотивам вселенной S.T.A.L.K.E.R.»** в дисклеймере и
  README — номинативное добросовестное использование (описание источника
  вдохновения, не источник путаницы). Это стандартная и защитимая форма.
  Убрать упоминание полностью — тоже вариант, дисклеймер не обязателен,
  но с ним безопаснее.
- **GitHub-репо называется StalkerReverT** — витрина проекта. Переименовать
  на GitHub (Settings → Rename; старые ссылки будут редиректить). Ссылки в
  README продолжат работать через редирект, но их стоит обновить.
- **Имена файлов релизов** stalker-revert-pc.zip / stalkerrevert.apk в
  старых релизах — исторические; в новых публиковать как
  bunker-zona-pc-vX.Y.Z.zip / bunker-zona-vX.Y.Z.apk.
- **Внутренние доки** (AGENTS.md, VERSIONING.md, журналы) упоминают старый
  кодомен — риск ~0 (не витрина), трогать не нужно.

## 4. Чек-лист владельца перед публикацией

1. **GitHub**: переименовать репо (StalkerReverT → BunkerZona или иное без
   «stalker»); обновить ссылки в README (пока работают редиректом).
2. **Скриншоты**: проверены все 3 в media/ — старого бренда в кадре нет;
   перед релизом переснять на актуальной версии (красивее).
3. **Google Play**: package уже уникальный (com.hakkiller.bunkerzona).
   ВАЖНО: APK перестанет обновляться «поверх» для тех, кто ставил старые
   сборки (смена имени пакета = новое приложение). Для GitHub-сиделоада
   это не важно; для Play — публикуем как новое приложение.
4. **Файлы релизов**: называть bunker-zona-*.zip / *.apk; в описании
   релиза не выносить S.T.A.L.K.E.R. в заголовок (в тексте «по мотивам» —
   допустимо).
5. **Страница стора**: название «Бункер: Зона / Bunker: Zona», без слова
   STALKER в заголовке/тегах.
6. Убедиться, что release-keystore не попадает в git (debug снят;
   .gitignore уже закрывает *.keystore — не добавлять с --force).

## 5. Монетизация (граница безопасного)

Сейчас: бесплатно, без рекламы, без покупок — риски минимальны.
Если появится монетизация (реклама/плато/донат) — дисклеймер «не
используется для извлечения прибыли» станет ложью, а фан-игра по мотивам
чужой вселенной с доходом — заметная мишень. Правило: любая монетизация =
сначала полная деговнизация бренда (убрать «по мотивам S.T.A.L.K.E.R.»,
переоценить все названия/образы) и консультация с юристом.
