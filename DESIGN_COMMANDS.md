# DESIGN_COMMANDS.md — очередь заданий для агента-архитектора

Этот файл читает **агент-архитектор**: он проектирует (дизайн-документы,
балансовые таблицы, спецификации, схемы UX) — но НЕ трогает код игры.
Основной агент (разработчик) встраивает его проекты в игру.

**ВАЖНО О ГРАНИЦАХ:** твоя очередь — ТОЛЬКО этот файл. Задания из
`COMMANDS.md` (поиск моделей, звука, текстур в интернете) — работа АГЕНТА-
ПОДГОТОВЩИКА: не выполняй их, даже если они кажутся проще. Если здесь
заданий не осталось — сообщи и жди.

## ПРОТОКОЛ ДЛЯ АРХИТЕКТОРА (читай внимательно)

1. **Бери задания сверху вниз**, по одному за заход.
2. Результат клади в **`design_inbox/<имя_задания>/`**: обязательный
   `README.md` (суть предложения в 10 строках — что, зачем, как встраивать)
   + сам документ(ы) в markdown. Таблицы баланса — markdown-таблицами или
   готовыми константами в код-блоках GDScript (как в `data/*_data.gd`).
3. **Не трогай код**: запрещено менять `*.gd`, `*.tscn`, `data/`, `core/`,
   `managers/`, `ui/`, `terrain/`, `entities/` и т.д. Только `design_inbox/`
   и этот файл.
4. **Не трогай**: `AGENTS.md`, `STATUS.md`, `COMMANDS.md` (это очередь другого
   агента), `README.md`, папку `inbox/` (материалы третьего агента).
5. Опирайся на факты проекта: читай `docs/*.md` (дизайны кампании/башни),
   `data/*_data.gd` (реальные константы баланса), `STATUS.md` (что сделано).
   Твои цифры должны биться с существующими системами, а не жить в вакууме.
6. Формат решений: всегда давай «ручки» — какие константы, где лежат,
   крайние значения, что подкрутить, если перебор.
7. **Выполнил задание — УДАЛИ его блок из этого файла.** Не вышло — допиши
   `> БЛОК: <причина>` и иди к следующему.
8. В конце захода — короткий отчёт: что спроектировано, что под вопросом.

## ЗАДАЧА D25: Ежедневные задания (дневной ритуал)

В игре есть недельные циклы (война/босс/calendar) и сезонные задачи
арены, но НЕТ ежедневных — причина заходить каждый день не сформулирована.
Спроектировать: (1) 3 задания дня из пула 10-12 (побей N сталкеров
аномалией конкретной стихии, пережи волну без потерь мутантов, сведи
выброс за 2 минуты, рейд гильд-босса, забег с пачкой только 1-3 звёзд,
убей босса календаря, 3 вызова арены, потрать 5000 биомассы, собери
артефакт...), детерминированный набор по seed даты; (2) прогресс в
сейве (event_state-паттерн уже есть — отдельное поле daily_tasks, не
мешать D24); (3) награды: биомасса/крутки/Искры/жегоны гильдии — по
тиру задания, всё за день (сброс в 04:00 локального); (4) UI: блок в
лаборатории (рядом с КАЛЕНДАРЁМ/ОХОТОЙ) + тосты выполнения; (5) локали
RU/EN. Учесть: задачи должны выполняться в ЛЮБОМ режиме (кампания/
выживание/охота), не ломать баланс раннего игры, офлайн-дружелюбно
(без серверного времени — локальное). Спеку класть в design_inbox/daily_tasks/.
ЗАВИСИМОСТИ: не стартовать, пока D24 live-ops не сольётся в git (общие
файлы lab_controller/localization — править по очереди, не параллельно).

## ЗАДАЧА D26: Онбординг новичка (первые 15 минут)

Новый игрок падает в лабораторию с 20 кнопками и не знает, что делать:
канон уже есть («ГОЛОС ЗОНЫ» - рассказчик, брифинг забега), но он не
ведёт за руку. Спроектировать онбординг: (1) сценарий первого запуска:
лаборатория -> возьми мутанта в пачку -> ВЫЛАЗКА -> поставь аномалию ->
заведи мутанта -> СТАРТ -> пережить 3 волны -> награда/гача; (2)
подсказки-стрелки/подсветка нужной кнопки (не модальные попапы на всё
экран), пропуск для опытных (флаг в сейве onboarding_done); (3)
сообщения Голоса Зоны в его тоне (сухой военный оператор); (4) очки
недопонимания: что такое энергия/биомасса/выброс, когда открываются
новые режимы (ОХОТА после N забегов? гейтинг кампании уже есть -
сверить); (5) мобильная раскладка подсказок. Прецеденты: брифинг
(BriefingData), story.gd C_GUIDE, run_popups. Спеку класть в
design_inbox/onboarding/. ЗАВИСИМОСТИ: нет, но встраивать после слияния
D24 (lab_controller общий).
