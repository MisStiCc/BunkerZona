# COMMANDS.md — очередь заданий для агента-подготовщика

Этот файл читает **второй агент** (подготовщик материалов). Он готовит ассеты
и данные, кладёт их в папку `inbox/` проекта с README внутри — а основной
агент (разработчик игры) встраивает их в код.

**ВАЖНО О ГРАНИЦАХ:** твоя очередь — ТОЛЬКО этот файл. Задания из
`DESIGN_COMMANDS.md` (дизайн-доки, баланс, UX-спеки) — работа АГЕНТА-
АРХИТЕКТОРА: не открывай их как свои и не выполняй. Если в этом файле
заданий не осталось — сообщи и жди, а не занимай чужие.

## ПРОТОКОЛ ДЛЯ ПОДГОТОВЩИКА (читай внимательно)

1. **Бери задания сверху вниз.** Одно задание = один заход. Не начинай новое,
   не закрыв предыдущее.
2. **Результат клади в `inbox/<имя_задания>/`** — внутри обязательно `README.md`
   (что это, для чего, что откуда, как названы файлы) и, если нужно,
   `CREDITS.md` (источник + лицензия каждого ассета).
3. **Лицензии — только свободные**: CC0 / CC-BY (с указанием автора) / ODbL
   (с атрибуцией). Источник записывай сразу. Нелегальное — нельзя.
4. **Не трогай код игры**: никаких изменений в `*.gd`, `*.tscn`, `data/`,
   `core/`, `managers/`, `ui/`, `terrain/` и т.д. Подготовщик только готовит
   материалы. Интеграцию делает основной агент.
5. **Не трогай**: `AGENTS.md`, `STATUS.md`, `README.md`, сейвы, `inbox/`
   чужих заданий, `assets/`, `models/` (это уже встроенное).
6. **Выполнил задание — УДАЛИ его блок из этого файла** (целиком, от
   `## ЗАДАЧА` до следующей `## ЗАДАЧА`). Это фиксация «сделано».
   Если задание не вышло — НЕ удаляй, а допиши в его блок строку
   `> БЛОК: <что случилось, что нужно человеку>`.
7. Форматы материалов: аудио — `.ogg` (loop для эмбиента/музыки задавай
   в README), модели — `.glb` (анимации внутри), текстуры — `.png/.jpg`,
   данные — `.json/.csv`.
8. Названия файлов — латиницей, без пробелов, как указано в задании
   (основной агент подключает их по путям из README).
