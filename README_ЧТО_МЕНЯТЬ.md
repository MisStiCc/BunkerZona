## 00. ГОРЯЧИЙ ФИКС №2: «Failed to load script zone_controller.gd — Parse error» при запуске забега

### Что происходит

панели ошибок висят «Не удалось разрешить глобальный класс SpawnManager»

смешанных отступов (часть строк на пробелах среди табов). Из-за него

### Что проверено у меня
Все 15 файлов пакета прогнаны сканером смешанных отступов — **0 смешанных
строк**, и всем 102 скриптам проекта через настоящий Godot 4.6.1 —
**0 ошибок компиляции**. Значит, виновник — файл, которого в пакете не было,
и который правился руками в редакторе (чаще всего это `spawn_manager.gd`:
при первой ошибке SpawnManager его могли править/дополнять вставкой из чата,
а чат рисует пробелы вместо табов).

### Что нового в пакете
1. **Добавлен `managers/spawn_manager.gd`** (табулированная версия из вашего
   дампа, `class_name SpawnManager` на месте) — теперь он заменяется пакетом,
   и его не нужно трогать руками.
2. В `zones/zone_controller.gd` вычищена единственная смешанная
   строка-комментарий (153).

### Что делать
1. ПОЛНОСТЬЮ закрыть Godot.
2. Заменить всё содержимое пакета поверх корня проекта (файлов теперь 15).
3. Удалить папку `.godot` в корне проекта (пересоздастся, первый запуск
   дольше обычного — это нормально).
4. Открыть проект и проверить вкладку «Ошибки».

### Обновление камеры (17.10): ПК-управление + варнинг «scale»

## 0. ГОРЯЧИЙ ФИКС (30.10.2026): Parse Error в game_camera.gd:80 и «Не удалось разрешить глобальный класс SpawnManager»

### Что было
В моей `scripts/game_camera.gd` из этого пакета строка 80 была написана в
синтаксисе сцены (.tscn), а не GDScript:

```
b.theme_override_font_sizes/font_size = 24        # ← так пишут в .tscn
b.add_theme_font_size_override("font_size", 24)   # ← так надо в коде
```

Парсер читал её как «b.theme_override_font_sizes ДЕЛИТЬ на font_size =
24» — отсюда ошибка «Only identifier, attribute access or subscript access
can be used as assignment target» и отказ загрузки всего скрипта.

### Каскад со SpawnManager — это следствие, файл у вас в порядке
`managers/spawn_manager.gd` существует и в нём правильный
`class_name SpawnManager` (проверено по вашему дампу). Пока в проекте есть
хоть один битый скрипт, редактор завершает разбор зависимостей на полпути и
кэш глобальных классов (`.godot/global_script_class_cache.cfg`) остаётся
устаревшим — поэтому `zone_controller.gd:22` не может разрешить SpawnManager.

### Что делать
1. Заменить `scripts/game_camera.gd` файлом из пакета (исправлен), либо
   руками поправить строку 80 на
   `b.add_theme_font_size_override("font_size", 24)`.
2. **Закрыть Godot**, скопировать файлы, открыть проект заново (или
   Проект → Перезагрузить текущий проект) — это перестроит кэш классов,
   и ошибка SpawnManager уйдёт. Не копировать файлы при открытом редакторе.
3. Контроль: проверено прогоном всех 102 скриптов проекта через настоящий
   Godot 4.6.1 — после фикса компилируется всё.

### ЕСЛИ ПОСЛЕ ЭТОГО ОШИБКИ ОСТАЛИСЬ: смешанные отступы (табы + пробелы)
В панели ошибок появляются строки вида «строки 24, 259, 288 — используются
пробелы вместо табуляции». Причина: в файле СМЕШАНЫ табы и пробелы. Так
получается, когда файл заменяется на диске при ОТКРЫТОМ редакторе (редактор
затем сохраняет свой старый буфер поверх нового файла) или когда куски кода
вставляются руками из чата (чат рисует табы пробелами). Мои zone_controller.gd
и hud.gd из первой раздачи были на пробелах, а весь проект — на табах,
что и создало смесь при частичной замене.

GDScript требует единообразных отступов: файл со смесью не компилируется,
и из-за него же падает «Не удалось разрешить глобальный класс SpawnManager».

**Восстановление (5 минут):**
1. ПОЛНОСТЬЮ закрыть Godot.
2. Заменить ЦЕЛИКОМ (не открывая, не редактируя, не копируя куски):
   - `zones/zone_controller.gd` — из пакета (теперь на табуляции);
   - `ui/hud/hud.gd` — из пакета (теперь на табуляции).
3. Не открывая Godot, удалить папку `.godot` в корне проекта — она
   пересоздастся сама (первый запуск дольше обычного, это нормально).
   Это полный сброс кэша глобальных классов.
4. Открыть проект. Если в панели «Ошибки» остались строки про пробелы:
   КЛИКНИ на строку ошибки — откроется файл на нужной строке; затем в
   редакторе скрипта ПРАВЫЙ КЛИК → «Преобразовать отступ в табуляцию»
   (Convert Indent to Tabs) → Ctrl+S.
5. Проект → Перезагрузить текущий проект.

**Правила на будущее:** файлы заменять только при закрытом Godot; заменять
файл целиком, никогда не мержить куски из чата; если нужно править вручную —
править в редакторе Godot (он сам ставит правильную табуляцию).

## 1. Предупреждение «Node './Visual' was modified from inside an instance, but it has vanished»

### Причина (найдена точно)
Сцены-мутанты наследуют `base_mutant.tscn`. В **базе мутанта** узел-меш
называется `MeshInstance3D`, а узла `Visual` там НЕТ вообще. Но в сценах
псевдопса и полтергейста остался оверрайд от шаблона сталкера (у сталкеров
узел действительно называется `Visual`, поэтому у них всё чисто):

```
[node name="Visual" parent="."]   # ← такого узла в base_mutant.tscn нет
visible = false
```

Godot при каждом `instantiate()` (прогрев `warmup_worker` и реальный спавн)
не находит узел и пишет предупреждение. На работу не влияет, но замусоривает
отладчик.

**Правильно** — прятать реальный меш-капсулу, как это уже делает кровосос:
`[node name="MeshInstance3D" parent="."] visible = false`.

### Файлы
| Файл из пакета | Куда в проект |
|---|---|
| `entities/mutants/pseudodog.tscn` | `entities/mutants/` (заменить) |
| `entities/mutants/poltergeist.tscn` | `entities/mutants/` (заменить) |

Больше ничего в сценах не тронуто — только блок оверрайда перенесён с
несуществующего `Visual` на реальный `MeshInstance3D`.

## 6. Управление на мобилке — РЕАЛИЗОВАНО (пан с инерцией + тап = ставить)

В проекте НЕ БЫЛО touch-управления: единственная камера — WASD + мышь,
на телефоне она мёртвая. Сделано по твоим ответам (пан с инерцией,
тап = ставить, pinch + кнопки):

**Мобильная камера (в `scripts/game_camera.gd`, ПК-поведение не тронуто):**
- старт: RTS-вид над монолитом (наклон ~60°, север вверх как на миникарте);
- один палец — пан «палец тянет карту», после отпускания — плавная инерция;
- два пальца — pinch-зум, высота 25–150 м с учётом рельефа;
- две круглые кнопки +/− над миникартой (появляются только на таче);
- двойной тап — плавное центрирование на монолите;
- тап по земле — прицеливание (см. ниже); тапы по кнопкам HUD камеру
  не ловят (используется _unhandled_input).

**Постановка «тап = ставить» (мобилка):**
- нажми кнопку аномалии/мутанта — она подсветится (режим кисти),
  тапай по земле — защита ставится в точки; повторное нажатие той же
  кнопки выключает кисть; другая кнопка переключает кисть на неё;
- на ПК всё по-старому: кнопка ставит на 10 м перед камерой.

| Файл из пакета | Куда в проект | Что внутри |
|---|---|---|
| `scripts/game_camera.gd` | `scripts/` (заменить) | WASD-полёт на ПК + вся мобильная схема |
| `core/signals.gd` | `core/` (заменить) | +1 сигнал `ground_tapped(world_position)` |
| `zones/zone_controller.gd` | `zones/` (заменить) | режим кисти: `set_pending_placement()` + постановка по тапу |
| `ui/hud/hud.gd` | `ui/hud/` (заменить) | на таче кнопки включают кисть вместо мгновенного спавна |
| `utils/helpers.gd` | `utils/` (заменить) | удалена сломанная и нигде не использованная `format_time()` (в ней была потеряна скобка — валит парсер файла) |

Сцену main.tscn менять НЕ нужно — камера та же, скрипт тот же файл.
